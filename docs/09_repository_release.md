# 仓库发布与质量边界

## 1. 发布目标

公开仓库用于展示可复现的数据链路、分析结论、模型验证、运营行动设计和实验框架。发布层不新增模型、不修改指标定义，也不把离线结果包装成真实线上收益。

## 2. 仓库应包含的内容

- README、架构、数据设计、指标字典、数据卡、模型卡和验证报告；
- dbt 分层模型、Python 分析与建模代码、Streamlit 看板代码；
- GitHub Actions、贡献说明、发布清单和必要的第三方声明；
- 聚合且脱敏的项目证据、案例报告和看板截图。

## 3. 不进入仓库的内容

- 原始 CSV、DuckDB、WAL、joblib 和逐商家或逐订单预测明细；
- `.env`、Streamlit secrets、本地 dbt 用户配置、虚拟环境和运行缓存；
- 仅供个人使用的准备材料。

`.gitignore` 对上述本地内容提供基础隔离，`scripts/validate_repository.py` 再检查候选文件体积、禁止文件类型、数据目录边界和常见私钥标记。

## 4. CI 与本地验收边界

GitHub Actions 无权访问被忽略的 Olist 原始数据，因此只验证代码契约、版本化证据结构、看板页面合成 fixture、实验模板、dbt 语法和仓库边界。

- `make ci`：无数据仓库检查、dbt parse 和全量 Python 测试；
- `make portfolio-check`：本地存在真实 artifacts 时，对账项目证据、检查内部链接和截图；
- `make verify`：从原始数据到 dbt、模型、分析快照和测试的完整复现。

三者验证层级不同，不能互相替代。

## 5. 发布前检查

1. `git status` 中没有原始数据、模型二进制、密钥或本地配置；
2. `make ci` 通过；
3. 需要更新业务数字时运行 `make verify`；
4. 看板截图来自当前代码与真实本地数据；
5. 数据许可、非商业用途和无真实 ROI/因果效果边界保持可见；
6. 根目录没有正式 `LICENSE` 时，不宣称项目采用某个开源许可证。
