# 真实业务落地手册（不含虚构执行结果）

## 1. 当前状态

当前项目已完成公开历史数据上的离线分析、模型排序、商家行动规则、实验样本量规划、稳定草案分组和四类日志契约。它尚未接入真实 CRM、工单、履约、成本或实验结果系统，因此本手册描述的是下一步执行条件，不是已经完成的上线。

## 2. 最小责任分工

| 角色 | 最小职责 | 上线前必须确认 |
|---|---|---|
| 业务 owner | 定义 P1 动作、资格池和停止条件 | 动作是否可标准化、是否会伤害商家体验 |
| 运营执行 | 按分组执行并记录状态 | SLA、失败原因枚举、是否允许补触达 |
| 数据分析 | 冻结指标、分组、成熟窗和 ITT 口径 | 分母、时区、评价成熟和重复执行规则 |
| 数据工程 | 接入资格、执行、订单、评价和成本数据 | 主键、事件时间、回填、迟到数据和权限 |
| 风控/法务 | 检查数据使用和干预边界 | 最小必要字段、保存周期、退出机制 |

## 3. 必需输入

1. 实验登记：实验 ID、owner、决策问题、资格规则、主指标、护栏、计划日期和版本；
2. 不可变资格快照：seller_id、干预前分层、入组时间、数据截止时间；
3. 发布分组：assignment_id、处理/对照、哈希和设计版本；
4. 真实执行：动作时间、状态、动作类型、匿名操作员、金额与币种；
5. 成熟结果：统一观察窗内订单、已交付、延迟、合法评价、低评分、取消、退款和 GMV；
6. 数据质量：缺失、重复、跨组、时间倒置、未成熟和污染标记。

## 4. 30/60/90 天路径

### 0–30 天：影子运行

- 只生成资格池和行动建议，不改变真实业务；
- 对比建议名单与运营人工选择，记录差异原因；
- 验证 seller_id 覆盖、事件时区、评价成熟时间和成本口径；
- 冻结动作 SOP、失败状态和护栏，不计算效果。

退出闸门：一对一主键通过；资格快照可复现；执行日志字段完整；隐私与权限评审完成。

### 31–60 天：小流量可行性

- 发布不可变分组，检查干预前平衡；
- 监控执行率、污染率、退出率和成熟率；
- 不因中间结果重新抽组或修改主指标；
- 若候选池仍只有约 158 个，不把统计不显著解释成无效果。

退出闸门：执行率和成熟率达到预注册阈值；无严重护栏恶化；日志链路完整。

### 61–90 天：跨周累计与正式分析

- 按预注册规则跨周累计新候选；
- 统一成熟窗后锁定数据；
- 先做 ITT，再把 per-protocol 作为敏感性分析；
- 报告绝对差、相对差、区间、护栏和成本，不只报 p 值；
- 成本、利润和增量证据不完整时仍不计算 ROI。

## 5. 停止条件

- 分组或资格快照被覆盖且无法恢复；
- 处理/对照发生系统性串组；
- 关键结果未成熟却被记为 0；
- 动作定义跨运营人员严重不一致；
- 评价覆盖、取消或退款护栏显著恶化；
- 成本或个人信息采集超出批准范围。

## 6. 上线后才可新增的结论

只有真实日志通过质量闸门后，才能写执行率、成熟率、处理/对照差异和区间。只有同时拥有可信增量效果、真实成本和收益口径后，才能讨论 ROI。任何未来结果都必须另建带日期的运行日志，不回写成当前公开历史数据阶段已经发生的事实。
