## 4. 真实问题与处理

- 首次创建环境时，沙箱禁止访问 `~/.cache/uv`。定位为权限限制后，按用户已批准的安装范围申请授权重试；
- `dbt --version` 会联网检查最新版，受限网络下返回非零状态。后续命令统一使用 `--no-version-check`，避免把更新检查失败误认为 dbt 不可用；
- dbt-core 1.12.0 安装时构建实验解析器，耗时约 7 分钟，但最终成功。
- 首轮单元测试为 9 通过、1 失败。失败发生在 Pandas 3.0 解析混合精度 ISO 时间字符串时；定位到新版不再按旧行为逐项推断。解析逻辑改为显式 `format="mixed"`，保留真实输入的兼容性，而不是简化测试数据。
- 首次 `dbt parse` 发现 dbt 1.12 的目录参数需要放在 `parse/build` 子命令之后；已修正 Makefile 命令顺序。这是 CLI 版本适配问题，尚未进入模型 SQL 解析。

## 7. 依赖安装决策与边界

### 7.1 为什么需要新环境

工作区初始只有系统 Python 3.9.6，而项目需要的 dbt、DuckDB、Pandas、scikit-learn、Plotly、Streamlit 和 pytest 均未检测到。没有使用系统 Python 直接安装，原因是：

- 系统 Python 版本偏旧，而新版 dbt/Streamlit/scikit-learn 的兼容边界更适合 Python 3.11+；
- 全局安装会影响用户其他项目，不满足可恢复和最小影响原则；
- 项目需要锁定可复现版本，不能依赖用户机器当时的全局包集合。

在向用户说明用途、预计体积、命令和风险并获得明确批准后，使用 Python 3.12.13 和 uv 在项目内创建 `.venv`。本操作没有修改系统 Python，没有写入系统配置，删除 `.venv` 即可恢复。

## 8. 文件级实现明细

| 文件 | 具体作用 | 为什么放在这一层 |
|---|---|---|
| `requirements.txt` | 锁定项目直接依赖版本 | 使他人能使用同一组主要版本复现 |
| `pyproject.toml` | 记录包名、Python 范围和 pytest 配置 | 集中工程元数据，减少分散配置 |
| `Makefile` | 统一环境检查、manifest、dbt、训练、分析、测试和看板命令 | 降低命令顺序和参数错误 |
| `.gitignore` | 忽略 `.venv`、原数据、DuckDB、artifacts、dbt target/logs 和敏感配置 | 防止大文件、可再生产物和敏感内容进入 Git |
| `.env.example` | 只保留非敏感配置名示例 | 说明配置接口，不保留真实凭证 |
| `configs/project.yml` | 数据目录、数据库、随机种子、Top-K 和隐私开关 | 将跨模块参数与代码分离 |
| `data/raw/README.md` | 规定 11 个原始 CSV 文件名和不入 Git 规则 | 让数据准备无需阅读 Python 代码 |
| `src/metrics.py` | 安全比率、成交率、延迟率、Top-K、WAPE | 避免模型、看板和测试重复实现公式 |
| `src/validation.py` | 特征黑名单、时间切分和基础断言 | 将泄漏防护从文档变成可运行规则 |
| `src/ingest.py` | 检查本地文件、计算字节数和 SHA-256、输出 manifest | 数据下载和数据验证分离，不把网络凭证写进项目 |
| `scripts/check_environment.py` | 打印 Python 和核心包实际版本 | “能 import”和“版本与报告一致”可同时验证 |

## 9. 基础测试覆盖了什么

- 分母为 0 时安全比率不伪造无穷大或随意 0；
- 延迟率只对同时存在实际与承诺时间的样本计算；
- Top-K 对 K=0、K 超过样本数、同分等边界有定义；
- WAPE 和 MAE 对分母为 0 的情况给出明确处理；
- 时间切分按日期块分配，同一天不能跨训练/验证/测试；
- 线索和低评分禁止字段一旦进入特征列表会立即失败；
- 混合精度 ISO 时间字符串在 Pandas 3.0 下使用 `format="mixed"` 解析。

## 10. 问题定位时间线

1. 第一次创建环境时，uv 尝试使用工作区外的缓存路径，被沙箱拒绝。这不是包解析错误；通过权限错误路径确认后，在已获用户批准的安装范围内申请授权重试。
2. dbt 版本查询命令的更新检查访问外网失败，但包本身可正常导入。通过 `--no-version-check` 将外网更新检查与本地 dbt 功能分离。
3. 基础测试的唯一失败来自 Pandas 3.0 的时间解析变化。查看失败样本后确认输入本身合法但精度混合，因此修改解析策略，没有删掉或统一化测试输入。
4. `dbt parse` 失败的根因是 dbt 1.12 CLI 子命令参数顺序，修正 Makefile 后解析成功。没有因此降级 dbt。
