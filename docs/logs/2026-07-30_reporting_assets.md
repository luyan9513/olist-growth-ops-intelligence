## 8. 从“结果待跑”到“真实结果版”的更新过程

本阶段最初为报告建立结构，因为数据尚未下载，“当前不能给出渠道建议”是当时正确结论。数据完成后，没有另建一套断开的最终报告，而是将原文件更新为真实运行版，保证 README 入口始终指向当前有效文档。

更新时遵循以下规则：

1. 数据行数、日期、渠道和商家结论只从 `analysis_snapshot.json` 或 DuckDB 查询取值；
2. 模型指标只从各任务 `metrics.json` 取值；
3. 报告中同时展示基线和选中模型，不只写候选分数；
4. 商家需求 WAPE 85.71% 和低评分校准不足必须保留，不因为对求职展示不利而删除；
5. 业务建议使用“优先调查、作为参照、建议实验”等与证据强度相符的措辞；
6. 不出现“实现 X% 业务提升”、“为公司创造收益”或真实 ROI。

## 11. 模型指标版本一致性问题

在最终训练管道重跑后，低评分随机森林的当前权威值为：PR-AUC 0.1946、Top 20% 精准率 19.39%、覆盖率 35.40%、Lift 1.77。早一次产物为 19.22%/35.09%/1.75，四舍五入后 PR-AUC 同为 0.195。

这次差异表明手工抄写指标存在版本漂移风险。处理方式为：

1. 以当前 `metrics.json` 为权威值；
2. 将报告、模型卡、访谈材料和日志中的 Top-K 明细同步；
3. 在日志索引中明确 artifacts 优先级高于阶段性日志数字；
4. 后续更理想的做法是生成报告数字表，而不是人工复制。
