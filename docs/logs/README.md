# 开发日志索引与阅读说明

## 1. 日志用途

本目录记录项目从空工作区到真实数据构建、模型训练、看板验证和最终文档验收的完整过程。日志的作用不是重述 README，而是保留以下可审计信息：

1. 每个阶段实际新增或修改了什么文件；
2. 每个文件或文件组承担什么职责；
3. 采用当前实现而不是其他方案的原因；
4. 真实出现的问题、定位证据、修复方法和复验结果；
5. 实际运行的命令、通过/失败结果及当时阶段边界；
6. 尚未解决的限制、风险和后续计划。

日志不记录密钥、Token、密码、个人隐私或敏感配置；不补写实际未发生的困难，不将合成测试或离线结果写成真实业务收益。

## 3. 如何理解阶段性语句

早期日志中的“尚未下载数据”、“待真实验证”等语句是当时阶段的真实状态，不是项目当前状态。为保留开发轨迹，这些语句不被改写成“当时已完成”。每份日志后部的“阶段闭环补记”或最终验收日志说明这些待验证项最终如何收敛。

## 4. 权威证据优先级

当日志中的早期运行值与后续重跑产物不一致时，按以下顺序判定当前权威值：

1. `artifacts/*/metrics.json` 和 `artifacts/analysis_snapshot.json`；
2. `data/processed/olist.duckdb` 中当前 marts；
3. `reports/models/`、`reports/technical_report.md`和 `reports/business_report.md`；
4. 阶段日志中带有运行时间背景的历史数字。

这一顺序可以避免将训练管道调整前的中间指标误认为最终发布值。
