## 1.6 P13 实施顺序与阶段门槛

1. 先确认仓库、CI、看板、岗位材料和真实运营五条改进线的权限与边界；
2. 参考当前 GitHub Actions 和 Streamlit 官方文档，固定配置版本与取舍；
3. 让作品集单测脱离被 `.gitignore` 排除的 artifacts，使公开仓库 CI 能运行全部 Python 测试；
4. 增加只读权限、依赖缓存、Python 3.12、pytest、dbt parse 和仓库卫生检查的 GitHub Actions；
5. 用 `.streamlit/config.toml`、Plotly 公共主题和原生折叠筛选优化界面，不依赖脆弱 DOM 选择器；
6. 四类岗位材料只改写同一批真实项目事实，保留“离线”“公开历史数据”“无真实 ROI/实验效果”边界；
7. 把真实业务下一步拆成 owner、输入数据、流程、质量闸门和 30/60/90 天检查点，不填虚构完成状态；
8. 重跑 CI 等价命令、快速验收、全量 Python、dbt 和真实浏览器截图，真实结果产生后再更新状态与日志。
