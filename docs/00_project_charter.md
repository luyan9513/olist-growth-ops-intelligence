# 项目章程

## 1. 项目定位

**项目名称：** 商家增长与履约运营智能平台  
**一句话定义：** 基于 Olist 公开匿名样本，把“线索获取 → 商家成交 → 商家经营 → 订单履约 → 用户体验”串成一套可追溯的离线分析、预测和运营决策系统。  
**目标岗位：** 数据分析、增长分析、商业分析、电商运营分析、BI 分析。

本项目的价值不在于堆叠模型，而在于用一致的数据口径回答三个连续问题：渠道带来的线索是否更容易成交；成交商家后续是否创造可持续经营价值；哪些订单、商家、品类或地区需要优先干预。

## 2. 业务使用者与决策

| 使用者 | 决策 | 主要产出 | 建议频率 |
|---|---|---|---|
| 增长运营 | 有限触达名额优先给哪些线索、复盘哪些渠道 | 渠道漏斗、线索优先级清单 | 周 |
| 商家运营 | 哪些商家应进入增长扶持或风险跟进名单 | 商家画像、经营分层、风险清单 | 周/月 |
| 履约运营 | 哪些订单和履约组合的体验风险更高 | 低评分风险排序、品类/地区拆解 | 日/周 |
| 经营分析负责人 | 指标是否一致、结论是否可复现 | 指标字典、质量报告、技术/业务报告 | 月/版本 |

## 3. 核心业务问题

1. 不同获客渠道在成交率、成交商家后续 GMV 和体验质量上有何差异？
2. 商家、品类、地区和履约特征与延迟、低评分风险如何共同变化？
3. 在固定触达或干预容量下，模型排序能覆盖多少真实成交或风险订单？
4. 商家/品类周度需求如何变化，哪些对象呈现高价值高增长、高价值高波动或低价值长尾特征？

## 4. 范围

### 范围内

- Olist Marketing Funnel 与 Brazilian E-Commerce 匿名公开样本的本地处理；
- DuckDB + dbt-duckdb 的 staging、intermediate、mart 分层与数据质量测试；
- 获客漏斗、渠道质量、商家经营、履约体验、画像与风险清单；
- 线索成交、订单低评分风险、商家/品类需求预测；
- Streamlit 多页看板和明确标注的历史数据情景模拟；
- 数据卡、模型卡、指标字典、技术报告、业务报告和面试材料。

### 范围外

- 真实广告花费、毛利和 ROI；
- 因果归因、线上增量效果或真实业务收益承诺；
- 实时特征服务、在线模型部署、自动触达；
- SKU 库存补货、定价优化、生产系统权限与个人数据；
- 对匿名地理信息进行个人或商户再识别。

## 5. 成功标准

### 工程成功

- 从空环境按 README 能完成环境创建、数据准备、`dbt build`、模型训练、测试和看板启动；
- 每个看板指标可追溯到 mart、dbt 模型和指标定义；
- 主键、非空、金额、时间顺序、关联完整性等测试可执行且失败可定位；
- 原始数据、DuckDB 文件、模型文件、密钥和本地环境不进入版本库。

### 分析成功

- 所有核心指标明确粒度、分子、分母、过滤条件、空值处理和适用边界；
- 三类模型使用时间切分并与可解释基线比较；
- 线索模型不使用成交后信息，低评分模型不使用预测时点后的履约和评价信息；
- 所有结果数字由实际运行生成；模型若未胜过基线也如实报告。

### 求职交付成功

- 读者只看 `docs/` 和报告即可理解业务目标、数据链路、技术取舍、验证证据、问题、结论和局限；
- README 提供可复现命令，面试指南能支撑 2 分钟介绍和 20 个常见追问；
- 5 条简历 bullet 中的量化内容全部引用实际产物，不使用占位数字冒充结果。
- 公共仓库候选文件可通过无数据 CI 和仓库卫生检查，四类目标岗位均有基于同一证据包的定制 Bullet；许可证、远端发布和真实部署仍由所有者人工决定。

## 6. 原则与约束

- 公开历史数据只支持相关性分析和离线模拟，不代表现实因果效果；
- 预测时点决定特征边界，任何晚于该时点才产生的数据均不可入模；
- 先保证口径、质量和可复现，再提高模型复杂度；
- 不为“高级感”引入云服务、分布式系统或无业务价值的组件；
- 未确认数据许可前不重新分发原始数据，发布时仅提供下载指引与数据哈希/清单。

- 已验证 `mql_id`、`seller_id`、`order_id` 能串联业务链；842 条成交中 1 条因时间倒置不进入有效成交口径；
- 已按线索首次接触、订单购买时间和周/月时间轴完成切分，精确截点见模型卡；
- 没有渠道成本和干预实验，因此只输出容量、覆盖率和“单位成本相同”情景，不输出 ROI；
- 2026-07-30 核对 Kaggle 官方数据页时，两份 Olist 数据均标注 CC BY-NC-SA 4.0；本项目按署名、非商业、相同方式共享边界使用，仍不提交原始数据。
- 2026-08-02 完成发布前工程与岗位包装，但没有创建远端仓库、公开部署或真实业务接入；真实落地必须通过 `10_real_world_rollout_playbook.md` 的数据、权限、动作和实验闸门。
