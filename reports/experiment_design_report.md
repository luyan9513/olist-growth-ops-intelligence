# 从行动清单到因果验证：P11 实验设计报告

## 技术摘要

P11 已把 P10 的离线商家行动清单扩展为可审计的实验前基础设施：使用 `seller_id` 作为分组单位，以稳定 SHA-256 哈希生成行序无关的处理/对照草案，提供两个独立比例的样本量与 MDE 规划，并为实验登记、分组、执行和结果建立四张空日志模板及自动校验。

当前没有真实运营执行或结果数据，所以本报告只回答“实验怎样设计、当前候选池能否支持目标精度”，不回答“干预是否有效”。所有分组均为草案，不是已发布实验；所有 MDE 均为规划假设，不是预计提升。

## 单周 P1 候选池不足以识别 3 个百分点变化

首个建议实验以 P1 履约护航商家为候选池，目标是检验标准化护航是否降低后续低评分率。当前真实 P10 快照有 158 个 P1 商家。

在基线低评分率假设为 14.19%、希望识别降低 3 个百分点、双侧 alpha 0.05、把握度 80%、50/50 分流的前提下，正态近似需要处理组 1,932、对照组 1,932，总计 3,864 个成熟样本。当前 158 个候选只对应约 12.10 个百分点的可检测下降，且还没有计入标签未成熟、无评价、未执行和商家内订单相关性。

| 规划项 | 结果 |
|---|---:|
| 当前单周 P1 候选 | 158 |
| 目标绝对 MDE | 降低 3.00 个百分点 |
| 规划总样本 | 3,864 |
| 处理组 / 对照组 | 1,932 / 1,932 |
| 当前池近似可检测 MDE | 降低 12.10 个百分点 |

这意味着不能把单周小样本实验的“不显著”解释为“没有业务价值”。更合理的做法是延长滚动入组周期、在不改变干预含义的前提下预先扩大资格池，或接受实验只能识别较大效果。

## 草案分组可复现，但小样本仍要检查平衡

默认草案实验 ID `draft_p11_fulfillment_guard_v1` 将 158 个候选分为处理组 82、对照组 76。活动档位分布为：处理组高档 64、中档 18；对照组高档 58、中档 18。该结果只用于验证分组机制和页面，不代表实验已启动。

哈希输入包含实验 ID、商家 ID 和设计版本，因此相同输入不受 DataFrame 行序影响；更换实验或版本会生成新序列。稳定哈希不保证小样本恰好 50/50，也不保证州、活动档位等维度自然平衡，所以发布前必须保存平衡表并按预注册方案判断是否使用分层随机，而不能反复换 ID 直到结果“好看”。

## 四表日志把资格、执行和结果分开

- 实验登记表冻结问题、资格、指标、时间、alpha、power 和版本；
- 分组日志保存不可变资格快照和组别，不用后续结果覆盖；
- 执行日志允许记录成功、失败、拒绝和多次尝试，同时保留非负成本与币种；
- 结果日志保存观察窗内订单、交付、延迟、评价、低评分、取消和金额的分子/分母。

校验代码会拒绝重复主键、未登记实验、非法组别、分组早于资格快照、执行早于分组、结果窗早于分组、负数/非整数计数，以及低评分数超过评价数等不可能关系。真实日志接入前，四张 CSV 只有表头，不提供示例业务行。

## 方法和假设

样本量采用两个独立比例的双侧正态近似；50/50 分流使用标准近似，非均匀分流使用相对 50/50 的效率修正。页面可以选择“风险降低”或“增长提高”方向，因为两种方向下备择率和方差不同。

该近似未自动考虑商家内多订单相关性、跨周重复入组、实验中途查看、多重指标、不执行、样本流失或评价缺失。真实实验应按商家聚类、结果成熟率和设计效应增加样本，并以意向处理（ITT）作为主分析。

## 限制与下一步

当前最重要的缺口不是算法，而是真实运营数据和组织流程。下一步应由业务负责人确认标准化干预内容、单次工时、资格是否能跨周滚动、结果成熟窗和互斥实验规则；然后在受控环境接入四张日志，先做分组与成熟度质量检查，再计算效果。

在真实结果日志到位前，不能报告显著性、置信区间、风险下降、订单增长、成本节省或 ROI。
